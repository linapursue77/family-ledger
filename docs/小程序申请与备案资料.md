## 0. 先做哪一步（时间线）

**最关键：域名 ICP 备案耗时最长（10–20 天），必须最先启动，否则会卡住后面所有步骤。**

| 顺序 | 事项 | 耗时 | 说明 |
|:---:|---|:---:|---|
| 1 | 买域名 + 服务器，提交**域名 ICP 备案** | 10–20 天 | ⚠️ 最长，先做 |
| 2 | 注册小程序账号（mp.weixin.qq.com） | 30 分钟 | 拿到 AppID |
| 3 | 主体认证（个人） | 1–3 天 | 微信认证 30 元 |
| 4 | **小程序备案** | 1–7 天 | 认证后才能备案 |
| 5 | 配置服务器域名 + 开发 | — | 依赖第 1 步完成 |
| 6 | 提审发布 | 1–7 天 | — |

> 第 1 步和第 2–4 步可以**并行**推进。

## 2. 小程序基础信息

位置：mp 后台 → 设置 → 基本设置

| 字段 | 建议值 |
|---|---|
| **名称** | `钱来钱往记账`（首选）<br>备选：`钱来钱往家庭账本`、`钱来钱往账本` |
| **头像** | 512×512 PNG，建议沿用 App 主色（米白底 + 💰 图标） |
| **简介** | 见下方「简介文案」 |
| **服务类目** | **工具 → 效率** |
| 关键词 | 记账、家庭账本、多人记账、借贷、收支、账本 |

### ⚠️ 名称风险提示

「钱来钱往」有三个已知风险：

1. **唯一性**：已有云南钱来钱往商贸、安徽钱来钱往金融信息咨询等企业，百度百科另有「钱来钱往」词条（中富通达投资担保品牌）。**必须先在注册页实测是否被占用。**
2. **类目误判**：带「钱」字且已有金融公司同名，审核可能判定为**金融业类目**，而个人主体选不了金融类目 → 驳回。
3. **商标**：第 36 类（金融）大概率有在先注册。

**规避办法**：加「记账」后缀。既能提高唯一性，又能明确工具属性，避开金融类目判定。

### 简介文案（选一条，20–120 字）

**A（推荐，突出差异点）**
> 家庭共享记账本。三本账分开记、总额一起看；私密消费有分寸，借钱来往单独成账；微信支付宝账单一键导入，AI 帮你分析收支。

**B（简洁）**
> 给一家人用的记账本。多人协同记账、借贷来往台账、账单导入、资产曲线与 AI 财务分析，数据清晰，隐私可控。

**C（保守，只描述已实现功能，降低「功能与描述不符」驳回风险）**
> 简洁的家庭记账工具：记一笔收支、导入微信支付宝账单、查看月度报告与分类趋势、管理借出借入。

> 建议：小程序页面补齐前用 **C**，补齐后用 **A**。

## 4. 小程序备案

位置：mp 后台 → 设置 → 小程序备案（需先完成认证）

法律依据：《互联网信息服务算法备案》/ 工信部要求，2023-09 起强制，**未备案无法上架**。

### 4.1 主体信息

| 字段 | 填什么 |
|---|---|
| 主体性质 | 个人 |
| 姓名 | 管理员本人 |
| 身份证号 | 本人 |
| 身份证有效期 | 按证件 |
| 身份证照片 | 正反面，四角完整、无反光 |
| 手机号 | 本人实名 |

### 4.2 负责人信息

|---|---|

| 身份证号 / 照片 | 同上 |
| 手机号 | 本人 |
| **人脸核身** | ⚠️ 管理员微信扫码做人脸识别，**必须由本人实时完成**，无法代办 |

### 4.3 小程序信息

| 字段 | 填什么 |
|---|---|
| 名称 | 与第 2 节一致 |
| 图标 | 与第 2 节一致 |
| 简介 | 与第 2 节一致 |
| 服务类目 | 工具 → 效率 |

> **前置审批**：只有涉及新闻、出版、教育、医疗、药品、医疗器械、文化、广播电视节目、网络游戏等才需要。

### 4.4 备案时长

## 5. 域名与服务器（依赖 ICP 备案）

### 5.1 域名 ICP 备案（最先启动）

在域名/服务器服务商处提交（阿里云、腾讯云等）：

| 项 | 说明 |
|---|---|
| 域名 | 建议 `.com` / `.cn`，如 `qianlaiqianwang.com` |
| 服务器 | 国内节点（**必须**，境外服务器无法备案） |
| 备案类型 | 网站备案 |
| 材料 | 身份证正反面、手机号、幕布照片（服务商邮寄或 APP 人脸核验） |
| 网站名称 | 建议填「钱来钱往记账」 |
| 网站内容 | 个人工具类应用 / 记账工具服务接口 |
| 时长 | 10–20 天 |

> ⚠️ 域名备案与小程序备案是**两套独立流程**，都要做。
> 备案期间域名无法对外服务，先把接口部署到临时地址或等备案完成。

### 5.2 小程序服务器域名配置

位置：mp 后台 → 开发 → 开发管理 → 开发设置 → 服务器域名

| 类型 | 填什么 | 本项目的接口 |
|---|---|---|
| **request 合法域名** | `https://api.你的域名.com` | 所有 REST 接口 |
| **uploadFile 合法域名** | `https://api.你的域名.com` | 账单导入上传 |
| **downloadFile 合法域名** | `https://api.你的域名.com` | CSV 导出下载 |
| socket 合法域名 | 暂不需要 | — |

> ⚠️ 必须 **https** 且**已 ICP 备案**；不带端口；每月只能修改 5 次。
> 当前 `miniprogram/app.js` 里 `apiBase` 是 `http://127.0.0.1:8001`，上线前必须改成 https 域名。

## 6. 用户隐私保护指引（备案必填）

位置：mp 后台 → 设置 → 服务内容声明 → 用户隐私保护指引

> ⚠️ **必须与实际代码行为完全一致**。虚报被抽查到会下架。
> 下面按本项目**实际代码**如实整理。

### 6.1 我们收集的信息

| 信息类型 | 用途 | 代码依据 |
|---|---|---|
| **手机号** | 注册账号、登录、家庭内查找成员 | `Login.vue` 手机号输入框 |
| **昵称** | 家庭内显示称呼 | `Login.vue` / `Family.vue` 昵称字段 |
| **微信 openid** | 仅在开通会员支付时，用于标识付款账户 | `WechatOpenidView` |
| **用户选择的账单文件** | 导入微信/支付宝账单 | `import.js` 的 `wx.chooseMessageFile` |
| **记账数据**（金额、分类、备注、商户、日期） | 用户主动录入，存储于自有服务器 | 记账核心功能 |

### 6.2 不收集

位置信息、通讯录、相册、摄像头、麦克风、剪切板、设备标识符（IMEI/MAC 等）。

> 小程序**不使用** `wx.getLocation`、通讯录、相册、`wx.chooseImage`，因此在隐私指引里不要勾选这些，
> 否则会与实际不符。

### 6.3 隐私指引文案（可直接粘贴）

```text
《钱来钱往记账 用户隐私保护指引》

本指引说明本小程序如何收集、使用与存储你的信息。

一、我们收集的信息
1. 手机号：用于注册账号、登录及家庭成员之间相互查找。
2. 昵称（选填）：用于家庭账本内显示你的称呼。
3. 微信 openid：仅在你主动开通会员时，用于标识付款账户。
4. 你主动选择的账单文件：用于导入微信 / 支付宝账单，仅在你点击导入时读取。
5. 记账数据：你主动录入的金额、分类、备注、商户、日期等，用于生成账单与报表。

二、我们不收集
我们不会收集你的位置信息、通讯录、相册、摄像头、麦克风内容或设备标识符。

三、信息存储
上述数据存储于开发者自有服务器，仅用于为你提供记账服务，不会用于其他目的。

四、你的权利
你可以在「我的」页面修改昵称等信息，也可以联系我们删除账号及全部数据。

五、联系我们
如有疑问，可通过小程序内「我的」页面联系开发者。
```

## 7. 支付开通（二选一）

### 方案 A：个人主体 · 虚拟支付

| 项 | 内容 |
|---|---|
| 前提 | 个人主体 + 完成认证 + 完成备案 + 类目为「工具」 |
| 入口 | mp 后台 → 支付与交易 → 虚拟支付 |
| 审核 | 约 5 分钟自助开通 |
| 可卖 | 会员、功能订阅等虚拟商品 |
| 限额 | 月 10 万元 |
| 费率 | Android 1%（T+3 结算）；**iOS 12%（45–60 天结算）** |
| 技术 | `wx.requestVirtualPayment`，服务端用 **OfferID + AppKey + HMAC-SHA256** 签名 |

> ⚠️ 与后端已实现的**标准微信支付 v3 不通用**（v3 用 mchid + API 证书 + RSA 签名）。
> 选 A 需要后端另写一套虚拟支付适配，预计半天到一天。

### 方案 B：个体工商户 · 标准微信支付

| 项 | 内容 |
|---|---|
| 前提 | 注册个体工商户营业执照（1–3 天下证） |
| 入口 | 微信支付商户平台 pay.weixin.qq.com |
| 费率 | 约 0.6%，T+1 结算，iOS 无额外抽成 |
| 技术 | **后端 `apps/membership/pay.py` 已实现，可直接用** |

### 怎么选

| | A 虚拟支付 | B 标准支付 |
|---|---|---|
| 门槛 | 无执照 | 需办个体户 |
| iOS 抽成 | 12% | 无 |
| 结算 | iOS 45–60 天 | T+1 |
| 后端改动 | 需新写适配 | 已完成 |

> **建议**：先跑 A 验证付费意愿；月流水过万或 iOS 用户占比高时转 B。

## 9. 常见驳回原因（提前规避）

| 原因 | 规避办法 |
|---|---|
| 名称被占 / 判定金融类目 | 加「记账」后缀；避开「钱庄、金融、理财、贷款」等词 |
| 类目与功能不符 | 选「工具 → 效率」，**不要选金融业** |
| 缺少用户隐私保护指引 | 必须配置，且与代码一致 |
| 隐私指引虚报（勾了没用的权限） | 只勾手机号 / 昵称 / 文件，其余不勾 |
| 无法登录体验 | 提供可用的测试账号密码 |
| 功能与简介不符 | 页面未补齐时，用保守版简介（文案 C） |
| 前置审批选错 | 选「不涉及」 |
| 服务器域名未备案 / 非 https | 先完成 ICP 备案，配 https |
| 有「会员付费」但类目不符 | 个人主体只能走虚拟支付，且类目须为「工具」 |
